## 任务3：手工安装原理说明（SDK、工具链、PATH）

### SDK（Software Development Kit）

SDK 是开发特定平台应用所需的工具包集合。Flutter SDK 包含：
- **flutter tool**：命令行工具（`flutter create`、`flutter run`、`flutter build`）
- **Dart SDK**：Dart 编译器和运行时
- **引擎**：各平台（Android/iOS/Web/Windows）的渲染引擎二进制文件

安装原理：下载预编译的二进制压缩包，解压到本地目录即可，无需编译。Flutter 会在首次运行时自动下载各平台引擎。

### 工具链（Toolchain）

工具链是把源码变成可运行程序所需的全部工具：

| 工具链 | 用途 | 本项目中的来源 |
|--------|------|----------------|
| Dart 编译器 | 编译 Dart 代码 | Flutter SDK 内置 |
| Android SDK | 编译 APK | sdkmanager 安装 |
| Gradle | Android 构建系统 | 项目内 wrapper 自动下载 |
| MSVC (cl.exe) | 编译 Windows 桌面 exe | Visual Studio 2022 |
| Android Emulator | 运行模拟器 | sdkmanager 安装 |

### PATH 环境变量

PATH 是操作系统查找可执行文件的搜索路径列表。当你在终端输入 `flutter` 时：

1. 系统按 PATH 列表顺序逐个目录查找 `flutter.bat`
2. 找到 `C:\Users\HZL\dev\flutter\bin\flutter.bat` 后执行

**为什么要手动配置 PATH：** Flutter SDK 解压后不会自动注册到系统 PATH，需要手动添加 `bin` 目录，否则终端找不到 `flutter` 命令。

**User vs Machine 级别：** 我们用 User 级别（`[Environment]::SetEnvironmentVariable(..., "User")`），只影响当前用户，不需要管理员权限。

## 任务4：HelloWorld 代码逐行中文注释

```dart
// 导入 Flutter Material Design 组件库，提供按钮、文本、Scaffold 等 UI 组件
import 'package:flutter/material.dart';

// main() 是 Dart 程序入口，操作系统启动应用时从这里开始执行
void main() {
  // runApp() 将根组件 MyApp 挂载到屏幕上
  // const 表示 MyApp 是不可变配置，Flutter 可复用同一实例，提升性能
  runApp(const MyApp());
}

// MyApp 是应用的根组件，继承自 StatelessWidget（无状态组件）
// StatelessWidget 适合不需要动态改变内部状态的 UI
class MyApp extends StatelessWidget {
  // 构造函数，super.key 用于组件树中的标识和复用
  const MyApp({super.key});

  // build 方法返回该组件的 UI 描述
  // Flutter 框架调用此方法来渲染组件
  @override
  Widget build(BuildContext context) {
    // MaterialApp 是 Material Design 应用的外壳
    // 配置应用标题、主题和首页
    return MaterialApp(
      title: 'Flutter Demo',  // 应用标题（任务管理器中显示）
      theme: ThemeData(
        // 从种子色生成完整色板，deepPurple 为主色调
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.deepPurple),
      ),
      // home 指定应用的首页组件
      home: const MyHomePage(title: 'Flutter Demo Home Page'),
    );
  }
}

// MyHomePage 是首页组件，继承自 StatefulWidget（有状态组件）
// StatefulWidget 适合需要动态改变内部状态的 UI（如计数器）
class MyHomePage extends StatefulWidget {
  const MyHomePage({super.key, required this.title});

  // title 是从父组件传入的标题文本，final 保证不可变
  final String title;

  // createState 返回与此组件关联的 State 对象
  // Flutter 框架在创建组件时调用此方法
  @override
  State<MyHomePage> createState() => _MyHomePageState();
}

// _MyHomePageState 是 MyHomePage 的状态类，下划线前缀表示私有
// State 对象持有可变数据，当数据变化时调用 setState 触发 UI 重建
class _MyHomePageState extends State<MyHomePage> {
  // _counter 是计数器状态，初始值为 0
  int _counter = 0;

  // 按钮点击回调函数
  void _incrementCounter() {
    // setState() 通知框架状态已改变，触发 build 方法重新执行
    // 不调用 setState() 则 UI 不会更新
    setState(() {
      _counter++;  // 计数器加 1
    });
  }

  // build 方法构建首页的 UI 结构
  @override
  Widget build(BuildContext context) {
    // Scaffold 提供 Material Design 的基础页面结构（AppBar + body + FAB）
    return Scaffold(
      // AppBar 是顶部应用栏
      appBar: AppBar(
        // 背景色取主题色板的反色
        backgroundColor: Theme.of(context).colorScheme.inversePrimary,
        // 标题文本，widget.title 来自 MyHomePage 构造参数
        title: Text(widget.title),
      ),
      // body 是页面主体内容
      // Center 将子组件居中放置
      body: Center(
        // Column 将子组件按垂直方向排列
        child: Column(
          // mainAxisAlignment.center 使子组件在垂直方向居中
          mainAxisAlignment: MainAxisAlignment.center,
          // children 是 Column 的子组件列表
          children: [
            // 提示文本
            const Text('You have pushed the button this many times:'),
            // 计数值显示，$_counter 是 Dart 字符串插值语法
            // style 应用主题的 headlineMedium 文字样式
            Text(
              '$_counter',
              style: Theme.of(context).textTheme.headlineMedium,
            ),
          ],
        ),
      ),
      // FloatingActionButton 是右下角悬浮按钮
      floatingActionButton: FloatingActionButton(
        onPressed: _incrementCounter,  // 点击时调用 _incrementCounter
        tooltip: 'Increment',  // 长按提示文字
        child: const Icon(Icons.add),  // 按钮图标为"+"号
      ),
    );
  }
}
```

### 核心概念

- **`runApp(const MyApp())`**：Flutter 应用入口。将根 Widget 挂载到屏幕，Flutter 框架根据 Widget 树创建 Element 树和 RenderObject 树来驱动渲染管线。
- **`Widget`**：Flutter 中一切皆 Widget。Widget 是描述 UI 的不可变配置对象，本身不渲染。它描述"应该长什么样"，框架根据 Widget 树创建对应的 Element 和 RenderObject 来实际绘制。

## 任务5：AI 使用边界说明（何时人工介入）

### AI 适合做的

| 场景 | 示例 |
|------|------|
| 重复性操作 | 批量配置环境变量、生成脚本 |
| 知识检索 | 查询 Flutter API 用法、报错含义 |
| 代码模板 | 生成项目结构、样板代码 |
| 诊断建议 | 分析 flutter doctor 输出、定位报错原因 |

### 必须人工介入的场景

| 场景 | 原因 | 本项目实例 |
|------|------|------------|
| **系统级安装** | 需要管理员权限和 UAC 确认 | Visual Studio、Android Studio 安装 |
| **沙箱外执行** | AI 沙箱限制子进程存活 | Android 模拟器启动、flutter run |
| **认证凭据** | 涉及账号密码 | GitHub 推送认证（PAT Token） |
| **网络策略** | 需要判断网络环境选择镜像 | Gradle SSL 证书错误，需判断是国内网络拦截 |
| **架构决策** | 需要理解业务上下文 | 选择 API 版本（android-35 vs 36） |
| **安全敏感** | 涉及系统安全设置 | 关闭 PowerShell 执行策略限制 |

### 本项目中的人工介入节点

1. **winget 安装 VS/Android Studio** — AI 沙箱阻止 winget 写入系统数据库，需用户确认 UAC
2. **Android 模拟器启动** — AI 终端退出会杀死模拟器进程，需在系统终端运行
3. **GitHub 推送认证** — 需要用户手动输入 Personal Access Token
4. **Gradle SSL 修复** — AI 能定位报错，但判断用国内镜像还是导入证书需要人工决策
5. **热重载实验** — 按 `r` 键热重载需要人在运行的终端中交互操作

### 总结

AI 辅助开发的正确姿势：**AI 负责"怎么做"，人负责"做什么和为什么"**。AI 能快速执行指令和检索信息，但涉及系统权限、安全凭据、进程持久性和架构判断时，必须由人工介入完成。
